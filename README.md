# BurnWise Streamlit

เว็บจากเทมเพลตขาว–แดง–ส้ม มีภาพรวม สำรวจแปลง คุณภาพข้อมูล และเกี่ยวกับโครงการ

## วางไฟล์บน GitHub

| ตำแหน่งใน repository | ไฟล์ |
|---|---|
| `app.py` | โค้ดเว็บ |
| `requirements.txt` | ไลบรารีสำหรับ Streamlit Cloud |
| `.streamlit/config.toml` | ตั้งค่าธีมสีสว่าง |
| `README.md` | คู่มือนี้ |
| `data/burnwise_master_plots.csv` | CSV ผลแปลงจาก notebook รอบล่าสุด (จำเป็นสำหรับข้อมูลเริ่มต้น) |
| `data/burnwise_tambon_overview.csv` | CSV ภาพรวมตำบลจากรอบเดียวกัน (ไม่จำเป็น) |

ไม่มี ZIP และไม่มีข้อมูลโครงการจำลองปนในไฟล์ผลลัพธ์

หากยังไม่ใส่ CSV เว็บจะเปิดได้และแสดงคำแนะนำให้อัปโหลดทางแถบด้านซ้าย หรือเปิดโหมดข้อมูลจำลองที่มีป้ายชัดเจน โหมดจำลองไม่ใช่ผลโครงการ

## เปิดเว็บใน Streamlit Cloud

1. เปิด GitHub repository ของทีม เลือก **Add file → Upload files** ใส่ `app.py`, `requirements.txt` และ `README.md` ที่ระดับบนสุด แล้ว Commit
2. เลือก **Add file → Create new file** ตั้งชื่อ `.streamlit/config.toml` คัดลอกเนื้อหาไฟล์ config แล้ว Commit
3. สร้างโฟลเดอร์ `data` ในเครื่อง ใส่ CSV จากการรัน notebook รอบเดียวกัน เปลี่ยนชื่อเป็นชื่อในตาราง แล้วลากโฟลเดอร์ `data` ไปที่หน้า Upload files ของ GitHub ตรวจเส้นทางก่อน Commit
4. เข้า https://share.streamlit.io/ และเชื่อม GitHub เลือก **Create app** เลือก repository ของทีม, branch ที่ใส่โค้ด (เช่น `main`) และ Main file path = `app.py`
5. ใน Advanced settings เลือก Python 3.12 แล้วกด Deploy ไม่ต้องใส่ Earth Engine token หรือ Project ID
6. หากแก้เว็บเดิม ใช้ repository/branch เดิม เปลี่ยน `app.py`, `requirements.txt` และ config แล้ว Commit; Streamlit Cloud จะนำการเปลี่ยนแปลงไปใช้

อัปโหลดไฟล์ทางหน้าเว็บมีผลเฉพาะเซสชัน ไม่บันทึกกลับ GitHub ถ้าต้องการให้ทุกคนเห็นข้อมูลเดียวกัน ให้ใส่ไฟล์ใน `data/` ของ repository

## รันในเครื่อง

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

## รองรับข้อมูล 2 รุ่น

- รุ่นล่าสุด: ต้องมี `plot_id`, `tambon_name`, `plot_area_rai`, `burn_pct`, `burn_status`; สถานะเป็น `Burn`, `No Burn`, `Unknown` ตามต้นทาง
- รุ่นเดิม: ใช้ `tier` เป็น เขียว/เหลือง/แดง/ข้อมูลไม่เพียงพอ เว็บระบุว่าเป็น Tier เดิมและไม่แปลงเป็น Burn/No Burn เพราะตรรกะคนละแบบ
- คอลัมน์อื่นที่ใช้: `valid_observation_pct`, `unknown_pct`, `centroid_lat`, `centroid_lon`, `distance_to_collection_km`, `access_gap_index`, `exclusion_reason`, `needs_verification` หากไม่มี จะแสดงว่าไม่มีข้อมูล
- CSV เดิมอาจนิยาม `valid_observation_pct` เป็นเผา+ไถกลบ จึงไม่แสดงว่าค่านี้เป็น coverage ที่ตรวจสอบแล้ว
- Score Panel คำนวณจำนวนใหม่จากตารางหลักบนเว็บ ไม่ต้องอัปโหลดไฟล์ panel ที่อาจเป็นคนละรอบ

## กราฟและฐานข้อมูล

กราฟจำนวนแปลงใช้ตัวกรองตำบลและสถานะร่วมกัน รวม Unknown ในฐานร้อยละ กราฟภาพรวมตำบลจาก CSV เพิ่มเติมใช้เฉพาะตัวกรองตำบล ไม่กรองสถานะแปลง และใช้ฐานพื้นที่จาก notebook หากไม่ใส่ภาพรวม เว็บแสดงค่าเฉลี่ย burn_pct ต่อแปลงที่จัดสถานะได้ พร้อมระบุว่าไม่ใช่สัดส่วนพื้นที่เผาทั้งตำบล

แผนที่ใช้จุดกึ่งกลางจริงจาก CSV ไม่ใช่ขอบเขตแปลง แสดงสูงสุด 12,000 จุดแบบสุ่มคงที่ ตัวเลขสรุปใช้ข้อมูลครบ กราฟ scatter แสดงสูงสุด 6,000 แปลงที่ไม่ใช่ Unknown และมีตัวเลขครบ พร้อมแจ้งจำนวนบนเว็บ ตารางแสดง 1,000 แถวแรก แต่ดาวน์โหลดผลค้นหาได้ครบ

แผนที่พื้นหลังและฟอนต์ออนไลน์ต้องเชื่อมอินเทอร์เน็ต ไม่ต้องใช้ map API key

## ถ้ามีปัญหา

- CSV ว่าง: เปิด notebook ส่งออกตารางหลักใหม่ ตรวจว่ามีแถวข้อมูล ไม่สร้างไฟล์เปล่าเพื่อให้ชื่อครบ
- ไม่มี CSV: ใส่ `data/burnwise_master_plots.csv` หรืออัปโหลดบนหน้าเว็บ
- คอลัมน์ขาด/ID ซ้ำ/ค่าผิดช่วง: แก้ข้อมูลต้นทาง เว็บจะแจ้งชัดเจน ไม่เติมข้อมูลให้ดูครบเอง
- ข้อมูล GISTDA เดือนที่ขาด: ยังไม่ต้องเพิ่มในเว็บ ส่วนหลักใช้ได้ การประเมินเปรียบเทียบต้องรอข้อมูลอ้างอิงครบช่วง
- เมื่อใช้ CSV รอบใหม่ ให้เปลี่ยนไฟล์หลักและไฟล์ภาพรวมพร้อมกัน และระบุช่วงศึกษาทางแถบด้านซ้าย ช่วงศึกษานี้เป็นข้อความประกอบ ไม่ใช่การกรองเวลา

การทดสอบของไฟล์นี้เป็นการทดสอบการแสดงผลและการอ่าน CSV ไม่ใช่การรับรองความถูกต้องของแบบจำลองการเผา
